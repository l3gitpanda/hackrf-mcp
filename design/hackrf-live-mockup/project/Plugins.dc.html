Decoder manifest

plugins/ism433/plugin.toml
[decoder]
id       = "ism433"
name     = "ISM433"
program  = "rtl_433"
args     = ["-r", "cs8:-", "-F", "json", "-M", "level"]
color    = "auto"            # next free palette slot

[tuning]
center_mhz = 433.62          # LO offset keeps 433.92 off the DC spike
rate_msps  = 2.0
channels   = [{ f = 433.92, label = "433.92", emission = "burst" }]

[record]
kinds   = ["sensor"]
subject = "{model}:{id}"
label   = "model"
level   = "rssi"
fields  = { temperature_C = "°C", humidity = "%", battery_ok = "bool" }

[views]
supports = ["table", "timeline", "waterfall"]   # no "map": no map layer

How a decoder or panel slots in

  1. Manifest, not code. A decoder declares its program, tuning, the kinds it emits, which field is the subject and which the label, typed fields and the views it supports.
  2. One registry. The service loads manifests and serves them at /api/registry. Every screen renders pickers, filters, legends, layers and alert fields from it.
  3. Generic first. A new kind gets the generic row (subject, label, fields table, raw text), a feed item, timeline counts and a summary card without any UI work.
  4. Views are opt-in. Only kinds with a position and "map" get a map layer; the waterfall uses the channel’s emission hint.
  5. Panels fill slots. A panel names a slot and a query; screens render whatever is registered for their slots.
# plugins/squawk-board/panel.toml
[panel]
id     = "squawk-board"
title  = "Squawk board"
slot   = "summaries.card"   # live.health · map.side · log.drawer · summaries.card
query  = { kinds = ["aircraft"], fields = ["squawk", "callsign"], window = "1h" }
render = "table"            # table · list · stat · sparkline
