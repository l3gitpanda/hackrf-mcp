Adding a panel

A panel is a small file, data and no code, in the panels folder on the station. It is read on every page load: no restart. This screen can't create or change one. Fields are those an alert rule may test; a panel never shows a row's raw text or pager text.

[panel]
title = "Emergency squawks"
slot = "summaries.card"   # a card on the Summaries screen
render = "table"          # table, list or stat

[query]
profiles = ["adsb"]
fields = ["squawk", "callsign"]
group_by = "subject"      # or one of the fields
sort = "last"             # last, rows or messages
limit = 20
window = "24h"            # optional: else the screen's period
filter = [{ field = "squawk", op = "any_of", values = ["7500", "7600", "7700"] }]

The filter takes the same conditions as an alert rule: any_of, equals, matches (a * and ? pattern), gt and lt, all of which must hold.

Adding a decoder

A decoder is a Python module in the fork's src/hackrf_mcp/protocols/: it registers its capture decoder and live profile, names the kinds of rows it logs, which field is the subject and which the label, and the views it supports. Every screen, the MCP tools and the alert fields come from those registries, so nothing else changes.

Its program, if it runs one, has to be in the worker image, so a new decoder is a pull request, a new image and a re-pinned stack, like any other change. The README's "Adding a decoder" walks through one.
